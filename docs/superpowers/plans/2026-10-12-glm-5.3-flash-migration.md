# GLM-5.3-Flash Migration + Video Ingestion — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Qwen3-VL with GLM-5.3-Flash (Z.ai) for image + scanned-PDF OCR, add video ingestion (`.mp4/.mkv/.mov`) as a full RAG input, and remove every Qwen remnant.

**Architecture:** One new `GLMParser` (OpenAI SDK pointed at Z.ai) with three entry points — image, PDF-pages, video — slotting into the existing `ParserRouter` decision table; video markdown uses `## [mm:ss]` headers so the existing chunker/index/chat pipeline works unchanged.

**Tech Stack:** `openai>=2.33` (Z.ai is OpenAI-compatible), `tenacity` retry, `pillow` image normalization, existing `OcrCache`, Gradio UI untouched structurally.

**Spec:** `docs/superpowers/specs/2026-10-12-glm-5.3-flash-migration-design.md`

## Global Constraints

- Python ≥3.12; run everything through `uv` (`uv run pytest`, `uv run python …`). Shell is PowerShell — no Unix coreutils.
- **No new dependencies.** `openai`, `tenacity`, `pillow`, `pypdfium2` are already in `pyproject.toml`.
- **Owner commits.** Each task ends with `git add <files>` (staging only) + a suggested imperative message; the human runs `git commit`. Never commit `.env` (it is gitignored).
- Never print `.env` values; edit `.env` only via scripted line transforms.
- Settings field names are exact: `ZAI_API_KEY`, `ZAI_BASE_URL`, `GLM_MODEL`, `GLM_REASONING_EFFORT`, `GLM_MAX_TOKENS`, `GLM_VIDEO_MAX_UPLOAD_MB`. Defaults: base URL `https://api.z.ai/api/paas/v4/`, model `glm-5.3-flash`, effort `low`, max tokens `8192`, video cap `20`.
- Parser provenance strings: `"docling"`, `"passthrough"`, or the resolved model code (e.g. `"glm-5.3-flash"`). `"qwen3-vl"` must not appear anywhere in `src/` or `tests/` after Task 8.
- Request params to Z.ai: `temperature=1.0`, `top_p=0.95`, `reasoning_effort=settings.GLM_REASONING_EFFORT`, `max_tokens=settings.GLM_MAX_TOKENS`, header `Accept-Language: en-US,en`. No `thinking` parameter.
- Z.ai limits enforced: images ≤5 MB and ≤6000×6000 px (normalize oversized input via Pillow to JPEG q=90); video formats mp4/mkv/mov; video size guard default 20 MB (base64 inflates ×1.33).
- Functions ≤60 lines, files <500 lines; comments explain why.

## Review Focus

1. **Phone-photo JPEG >5 MB** — expect auto re-encode (JPEG q=90, ≤6000 px) and a successful OCR, not an API rejection. → `test_normalize_reencodes_over_size_limit` (Task 3)
2. **`.webp` upload** — expect PNG/JPEG normalization (Z.ai docs list jpg/png/jpeg only), not a hard failure. → `test_extract_image_webp_normalized` (Task 3)
3. **Video >20 MB (default guard)** — expect `GLMParserError` with actionable guidance before any network call. → `test_video_size_guard_blocks_oversized` (Task 4)
4. **Z.ai rejecting base64 video payload** — expect `GLMParserError` carrying the API message + public-URL hint, not a crash or wrong-video fallback. → `test_video_payload_rejection_includes_hint` (Task 4)
5. **Scanned PDF with `ZAI_API_KEY` missing** — expect Docling fallback with a warning; video instead raises a clear `ValueError`. → `test_pdf_falls_back_to_docling_when_glm_unconfigured`, `test_video_unconfigured_raises_valueerror` (Task 5)
