# Design: Replace Qwen3-VL with GLM-5.3-Flash (Z.ai) + video ingestion

**Date:** 2026-10-12
**Status:** Approved design — pending implementation plan
**Scope:** Phase 2 ingestion (image OCR, scanned-PDF OCR) engine swap; new video input format; Qwen removal app-wide.

---

## 1. Context

AdaptiveRAG converts uploaded files to markdown, chunks them, and indexes them into a hybrid
(dense + sparse) Qdrant collection for grounded chat. Today two ingestion paths call
**Qwen3-VL** (DashScope, OpenAI-compatible endpoint):

1. **Images** (`.png`, `.jpg`, `.jpeg`, `.webp`) — single VLM call per file.
2. **Scanned PDFs** (born-digital heuristic: <150 extractable text chars in first 3 pages,
   or user "force OCR" toggle) — pages rendered to PNG via `pypdfium2`, one VLM call per
   page, results cached by SHA256 of page bytes.

The owner is replacing Qwen entirely with **GLM-5.3-Flash via Z.ai** and adding a third
vision path: **video files** analyzed by the same model, producing timestamped markdown that
flows through the existing chunk → index → chat pipeline.

### References

- Example implementation (video): `zai-glm-implementation/glm_video_zai.py`
- Z.ai Chat Completion API reference: https://docs.z.ai/api-reference/llm/chat-completion
- GLM-5.3-Flash model guide: https://docs.z.ai/guides/vlm/glm-5.3-flash

### API facts (verified 2026-10-12 against docs.z.ai)

- Endpoint: `POST https://api.z.ai/api/paas/v4/chat/completions`; OpenAI-compatible; the
  existing `openai` SDK works with `base_url="https://api.z.ai/api/paas/v4/"`.
- Vision model codes: `glm-5.3-flash`, `glm-5.3-flashx` (vision request schema enum).
- **Image block:** `{"type": "image_url", "image_url": {"url": <public URL or base64 data URL>}}`
  — ≤5 MB per image, ≤6000×6000 px, supports **jpg/png/jpeg only**.
- **Video block:** `{"type": "video_url", "video_url": {"url": <URL>}}` — ≤200 MB, formats
  `mp4`/`mkv`/`mov`. Officially documented for public URLs; base64 data URLs for local video
  are undocumented but used by the owner's example script (treated as experimental).
- **Recommended params:** `temperature=1`, `top_p=0.95`, `reasoning_effort ∈ {low, high, max}`
  (default `max`), `thinking.type` must be `enabled` (cannot be disabled — omit it).
- Max output tokens: 131072 (128K). Header `Accept-Language: en-US,en` supported.

## 2. Goals / Non-goals

**Goals**

1. All image + scanned-PDF OCR runs on GLM-5.3-Flash through Z.ai, keyed by `ZAI_API_KEY`.
2. Video files (`.mp4`, `.mkv`, `.mov`) are first-class inputs: analyzed by GLM → markdown →
   chunked → indexed → searchable in Chat with citations. Works in both Ingest and Convert tabs.
3. Zero Qwen remnants: parser module, settings, UI copy, tests, `.env.example`, README,
   ARCHITECTURE.md, footer links.
4. Preserve the existing pipeline shape: file detection → parser routing → markdown →
   header-aware chunking → hybrid index. Docling and passthrough paths unchanged.

**Non-goals**

- No public-URL video input in the UI (local upload only; documented URL mode is a future option).
- No ffmpeg transcoding pipeline for oversized videos (size guard + clear error instead).
- No change to chat synthesis / router / SQL models (they are OpenAI models, untouched).
- No `PROJECT_PLAN.md` rewrite (historical phase log stays as-is).
- No auto-fallback to a demo video URL (analyzing the wrong video is worse than failing).

## 3. Detailed changes

### 3.1 New: `src/core/glm_parser.py`

Replaces `src/core/qwen_parser.py` (deleted). One class, one client, three entry points.

```python
class GLMParserError(Exception): ...

class GLMParser:
    def __init__(self, api_key=None, model=None, base_url=None,
                 reasoning_effort=None, cache=None): ...
    # reads settings.ZAI_API_KEY / ZAI_BASE_URL / GLM_MODEL / GLM_REASONING_EFFORT,
    # raises GLMParserError when the key is missing,
    # builds OpenAI(api_key, base_url, default_headers={"Accept-Language": "en-US,en"})

    def extract_image(self, file_path) -> str          # single image → markdown
    def extract_pdf_pages(self, file_path, progress=None) -> str
        # identical shape to QwenParser.extract_pdf_pages:
        # iter_pdf_page_pngs → per-page cache → "<!-- page N -->\n\n<md>" blocks
    def extract_video(self, file_path) -> str          # whole video → timestamped markdown

    model_name: str                                    # resolved model code (for provenance)
    @staticmethod is_configured() -> bool              # bool(settings.ZAI_API_KEY)
```

Internals:

- **`_call_glm(blocks, *, max_tokens=None) -> str`** — one chat completion with
  `temperature=1.0`, `top_p=0.95`, `reasoning_effort=settings.GLM_REASONING_EFFORT`,
  `max_tokens=settings.GLM_MAX_TOKENS`, tenacity retry (3 attempts, exponential 2–10 s) on
  `RateLimitError / APIConnectionError / APIError` — same `_RETRYABLE` tuple as today.
  Non-retryable failures → `GLMParserError` wrapping the API message.
- **`_image_data_url(path)`** — mime suffix from extension; `.jpg/.jpeg/.png` pass through as
  base64 data URLs; **`.webp` (and any other image type) is normalized to PNG in-memory via
  Pillow** (Z.ai supports jpg/png/jpeg only; Pillow is already a dependency).
- **`_normalize_image_bytes(raw, mime)`** — if raw bytes > 4.5 MB or longest side > 6000 px
  (Z.ai limits: 5 MB / 6000×6000), re-encode with Pillow: downscale to fit 6000 px long side,
  save as JPEG quality 90. Otherwise return unchanged. Applies to uploaded images only —
  rendered PDF pages (~144 DPI) are far below both limits.
- **`_video_data_url(path)`** — base64 data URL with mime from `mimetypes.guess_type`
  (default `video/mp4`); **size guard** first: file size > `GLM_VIDEO_MAX_UPLOAD_MB` →
  `GLMParserError` with actionable message (raise the limit / trim the clip / host publicly).
- **`_strip_outer_fence`** — carried over verbatim from `QwenParser`.
- **Cache**: `OcrCache` (unchanged module) keyed on the exact bytes sent to the API
  (post-normalization), so cache hits and API payloads always agree. Cached entries produced
  by Qwen remain valid markdown and are reused.
- **Prompts**: `OCR_PROMPT` reused verbatim (deterministic extraction rules). New
  `VIDEO_PROMPT`: complete markdown record of the video — `## [mm:ss]` timestamped sections;
  transcribe spoken dialogue; identify speakers; capture on-screen text; describe notable
  visuals/events; markdown only, no preamble, no code fence.

## 4. Error handling summary

| Failure | Behavior |
|---|---|
| `ZAI_API_KEY` missing | `GLMParserError` on parser construction; scanned-PDF path falls back to Docling with a warning; VIDEO path raises `ValueError` (no fallback) |
| Rate limit / transient API errors | tenacity retry ×3, exponential 2–10 s, then re-raise |
| Video over `GLM_VIDEO_MAX_UPLOAD_MB` | `GLMParserError` before any network call, actionable message |
| Z.ai rejects base64 video payload | `GLMParserError` passes API message through + hint that public-URL mode is the documented path |
| Image >5 MB / >6000 px | auto-normalized via Pillow before the call |
| Empty markdown result | existing warnings/`0 chunks` handling unchanged |

## 6. Risks / notes

- **Base64 video is undocumented** at Z.ai (official mode = public URL). Implemented with a
  size guard and honest errors; if Z.ai hard-rejects data-URL video, the fallback is
  hosting files publicly (future feature) — surfaced to the user, not silently worked around.
- **Gradio upload size**: no built-in cap by default; the GLM_VIDEO_MAX_UPLOAD_MB guard is
  the enforcement point.
- **Qwen-cached OCR entries remain valid** — cache keys are content hashes of the image
  bytes, not model names.
- **Provenance values change** for new ingests (`qwen3-vl` → model code); existing Qdrant
  metadata is untouched (historical rows keep their old value).
